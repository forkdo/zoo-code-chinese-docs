# Zoo Code 3.46 Release Notes (Combined)

这是 3.46 发布系列的合并视图，包含 3.46.0、3.46.1 和 3.46.2。

## 并行工具调用

当工作流受益时，Zoo 现在可以在一次响应中运行多个工具。这让模型可以更自由地批处理相互独立的步骤（读取、搜索、编辑等），而不必为每个工具单独发起一次 API 调用。这减少了多步骤任务中来回往返的轮次数，这类任务通常需要多次独立工具调用后才能提出或应用变更。([#11031](https://github.com/RooCodeInc/Roo-Code/pull/11031), [#11046](https://github.com/RooCodeInc/Roo-Code/pull/11046))

## read_file 工具全面重构

Zoo 现在默认限制文件读取行数（2000 行）以避免上下文溢出，并可根据需要对更大文件进行分页读取。当 Zoo 需要某行周围的上下文（例如堆栈跟踪指向第 42 行）时，它也可以请求包含该行所在的*整个*函数或类，而不是任意的“第 40–60 行”切片。在底层，`read_file` 现在有两种明确模式：**slice**（`offset`/`limit`）用于分块读取，**indentation**（以目标行为锚点）用于语义化提取。（感谢 pwilkin！）([#10981](https://github.com/RooCodeInc/Roo-Code/pull/10981))

## 终端处理重构

当命令产生大量输出时，Zoo 现在会限制其纳入模型上下文的输出量。被省略的部分会作为工件（artifact）保存。Zoo 随后可以按需对完整输出进行分页或搜索，这样大型构建和测试运行依然可调试，而无需将整个日志塞入每次请求中。([#10944](https://github.com/RooCodeInc/Roo-Code/pull/10944), [#11056](https://github.com/RooCodeInc/Roo-Code/pull/11056))

## 设置中的技能管理

你现在可以在设置面板中创建、编辑和删除技能，并带有内联校验和删除确认。编辑技能会在 VS Code 中打开 `SKILL.md` 文件。技能仍然以磁盘文件形式存储，但这让日常维护更快——尤其当你同时维护**全局**技能和**项目**技能时。（感谢 SannidhyaSah！）([#10844](https://github.com/RooCodeInc/Roo-Code/pull/10844))

## Provider 迁移至 AI SDK

我们已开始将各 provider 迁移到统一的 Vercel AI SDK 基础之上，使流式输出、工具调用和结构化输出在各 provider 之间表现更一致。在此版本中，该迁移包含共享的 AI SDK 工具，以及针对 Moonshot/OpenAI 兼容、DeepSeek、Cerebras、Groq 和 Fireworks 的 provider 迁移，同时还改进了 provider 错误（如速率限制）的呈现方式。([#11047](https://github.com/RooCodeInc/Roo-Code/pull/11047), [#11063](https://github.com/RooCodeInc/Roo-Code/pull/11063), [#11079](https://github.com/RooCodeInc/Roo-Code/pull/11079), [#11086](https://github.com/RooCodeInc/Roo-Code/pull/11086), [#11088](https://github.com/RooCodeInc/Roo-Code/pull/11088), [#11118](https://github.com/RooCodeInc/Roo-Code/pull/11118))

## 质量改进（QOL）

* **首次启动时导入设置**：在全新安装、尚未配置 provider 之前，你可以直接在欢迎界面导入设置文件。（感谢 emeraldcheshire！）([#10994](https://github.com/RooCodeInc/Roo-Code/pull/10994))
* **从技能 UI 更改技能的模式**：你可以使用下拉菜单设置技能所针对的模式（包括“任意模式”），而不必在模式文件夹之间手动移动文件。（感谢 SannidhyaSah！）([#11102](https://github.com/RooCodeInc/Roo-Code/pull/11102))

## Bug 修复

* **更可靠的工具调用历史**：修复了对话历史中 `tool_use`/`tool_result` ID 不匹配可能导致工具执行中断并抛出 `ToolResultIdMismatchError` 的问题。([#11131](https://github.com/RooCodeInc/Roo-Code/pull/11131))
* **MCP 工具结果可包含图像**：修复了返回图像的 MCP 工具（例如 Figma 截图）可能显示为“（无响应）”的问题。（感谢 Sniper199999！）([#10874](https://github.com/RooCodeInc/Roo-Code/pull/10874))
* **通过 LiteLLM 使用 Bedrock 时压缩更可靠**：修复了当历史中包含工具使用/工具结果块时，对话压缩可能失败的问题。([#10975](https://github.com/RooCodeInc/Roo-Code/pull/10975))
* **命令执行期间消息不会丢失**：修复了命令仍在运行时发送的消息可能丢失的问题；这些消息现在会被排队，并在命令结束时送达。([#11140](https://github.com/RooCodeInc/Roo-Code/pull/11140))
* **OpenRouter 模型列表刷新遵循你的 Base URL**：修复了刷新 OpenRouter 模型列表时忽略已配置的 Base URL、始终调用 openrouter.ai 的问题。（感谢 sebastianlang84！）([#11154](https://github.com/RooCodeInc/Roo-Code/pull/11154))
* **更可靠的任务取消与排队消息处理**：修复了在 VS Code 扩展与 CLI 之间取消/关闭任务或更新排队消息时行为可能不一致的问题。([#11162](https://github.com/RooCodeInc/Roo-Code/pull/11162))

## 其他改进

* **更干净的 GitHub issue 模板**：从 issue 模板选择器中移除了“Feature Request（功能请求）”选项，以便将功能请求引导至 Discussions。([#11141](https://github.com/RooCodeInc/Roo-Code/pull/11141))
* **缺少 `.env` 文件时启动更安静**：当可选的 `.env` 文件未被使用时，避免产生嘈杂的 `[MISSING_ENV_FILE]` 控制台输出。([#11116](https://github.com/RooCodeInc/Roo-Code/pull/11116))

## Provider 更新

* **代码索引嵌入模型迁移（Gemini）**：通过将请求从已弃用的 `text-embedding-004` 迁移到 `gemini-embedding-001`，保持代码索引功能正常工作。([#11038](https://github.com/RooCodeInc/Roo-Code/pull/11038))
* **Mistral provider 迁移至 AI SDK**：在保留 Codestral 支持和自定义 Base URL 的同时，提升了流式输出与工具处理的一致性。([#11089](https://github.com/RooCodeInc/Roo-Code/pull/11089))
* **SambaNova provider 迁移至 AI SDK**：改进了流式输出、工具调用处理和用量上报。([#11153](https://github.com/RooCodeInc/Roo-Code/pull/11153))
* **xAI provider 迁移至专用 AI SDK 包**：在使用 Grok 模型时，提升了流式输出、工具调用和用量上报的一致性。([#11158](https://github.com/RooCodeInc/Roo-Code/pull/11158))
